# Crown Index — Conversation Recovery Record

This file records the Crown Index architecture recovered from prior Kris Watson conversations and uploaded prototypes before implementation in C13b0.

## Recovered system identity

Crown Index is not simply a conventional web crawler. It is the searchable crown or registry above the Infinity machine network. It joins:

```text
Crown Index
├── Infinity Portal
├── Treasury
├── repository machines
├── Infinity AI
├── StarQuest
├── Star Coin
├── Avatar Coin
├── Builder Agent
├── Research Agent
├── Token Manager
└── marketplace and provenance records
```

## Repository-machine architecture

The prior system describes the Infinity organization as a network in which each repository can function as a machine. Crown Index is linked with Portal and Treasury and must discover, identify, rank, and route those machines.

It must index both public web resources and Infinity-native entities.

## Search process

The recovered search behavior is:

```text
user question
→ extract meaningful search terms
→ search local Infinity knowledge first
→ search multiple public sources
→ retain source links
→ cross-reference results
→ calculate confidence/stance
→ explain the result
→ add verified knowledge to the graph
```

Recovered stance progression:

```text
LEARNING
SEARCHING
REASONING
INFORMED
ANALYTICAL
MONGOOSE-COLD
VECTOR-TRUTH
```

These states should indicate evidence coverage, not pretend that repeated searching automatically guarantees truth.

## Crown creation sequence

Prior prototypes showed the sequence:

```text
idea or search topic
→ website
→ token
→ research
→ tool
```

and displayed a Crown step within the creation sequence. The full interpretation is:

```text
search/find
→ Crown evidence bundle
→ AI plan
→ website or experience
→ identity/coin attachment
→ review
→ publish
→ re-index
```

## AI site builder

The Builder must receive more than one result. It receives:

- user intent;
- diversified sources;
- local repository knowledge;
- citations;
- asset rights;
- project identity;
- related tools and pages;
- relevant token or coin records;
- security requirements;
- contradictions and unresolved questions.

The result can be:

- website;
- research page;
- tool;
- store or auction page;
- StarQuest world;
- creator page;
- coin or avatar page;
- scientific visualizer.

## Coins, tokens, and memory

Recovered prototypes connect search and creation activity with coins and tokens. They also preserve wallet snapshots and generate new records from saved system memory.

Crown Index must not equate an internal reward with financial value. It should distinguish:

- activity reward;
- utility token;
- collectible coin;
- Star Coin;
- Avatar Coin;
- speculative value;
- asking price;
- completed sale;
- coupon or access value.

## StarQuest use

StarQuest depends on Crown Index for persistent identities.

### Star Coin

Represents a creator, character, world, project, achievement, or approved identity.

### Avatar Coin

Represents the user-controlled visual identity used across StarQuest worlds and connected applications.

Each coin needs:

- permanent Crown ID;
- owner and creator references;
- image and previous versions;
- edition and serial;
- linked world and achievements;
- cards, coupons, media, notes, or access rights;
- verification and licensing states;
- wallet destination;
- recovery and revocation history;
- privacy and discoverability settings.

Typing a famous name is never identity verification.

## Search result structure

A Crown result should show:

- title;
- entity type;
- short explanation;
- source;
- confidence;
- trust/provenance state;
- creator/owner state;
- asset rights state;
- relationships;
- StarQuest compatibility;
- build action;
- save-to-Crown action.

## Ranking views

Crown Index needs separate ranking modes:

- Best Match
- Trusted
- New
- Original
- Infinity Network
- StarQuest
- Cards and Coins
- Research
- People and Creators
- Worlds and Experiences

Paid placement cannot secretly modify organic ranking.

## Scanner principles

The scanner may read:

- user-submitted URLs;
- public pages permitted for crawling;
- connected repositories;
- uploaded files;
- public APIs;
- feeds and sitemaps;
- manually submitted coin/avatar records.

It must not:

- bypass logins;
- collect hidden personal data;
- execute remote code;
- index credentials or private keys;
- copy protected assets into generated sites without rights;
- create false endorsements;
- ignore source restrictions;
- follow infinite URL traps.

## Interface direction

The page must behave like an app without requiring zoom:

- large search field;
- readable 18px or larger primary text on phones;
- result cards rather than tiny rows;
- fixed mobile actions;
- source and confidence panels;
- search graph visualization;
- direct Build from Results action;
- StarQuest coin/avatar filters;
- scanner status and indexed-machine count;
- no uniform desktop grid squeezed onto mobile.
