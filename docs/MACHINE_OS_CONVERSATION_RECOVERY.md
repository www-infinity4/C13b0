## 3. Octave architecture

Octave is a harmonization principle, not simple version duplication.

```text
Base machine
↕ complementary relationship
Octave2 machine
```

Recovered rule:

- duplicates are not automatically deleted;
- a related instance can operate at another octave, role, frequency, dimension, or processing layer;
- machines should complement rather than conflict;
- a prior report described 59 duplicate instances becoming 118 active machines across Base and Octave2.

### Octave registry fields

Every machine should eventually carry:

```yaml
machine_id: j
canonical_name: output-terminal
base_machine: j
layer: base
paired_machine: j-octave2
role: output-ui
frequency_role: presentation
status: recovery-pending
mounts: []
```

Possible layers:

- `base`
- `octave2`
- `archive`
- `nursery`
- `experimental`

An octave label must describe a real complementary role. It must not be used merely to avoid deciding which file is current.

## 5. Termux push workflow

The A–Z repositories were developed in a phone/Termux workflow. Recovery and future maintenance must favor:

- single-paste scripts;
- ordinary `git` and shell tools;
- no unnecessary package installation;
- clear local path and target repository display;
- branch and remote verification before push;
- non-destructive behavior;
- explicit failure output;
- no hidden OAuth or GitHub Actions dependency.

A recovered local path example included:

```text
~/z/j/index.html
```

A later problem showed `index.html` loading while `/styles.css`, `/app.js`, and `/app-token.js` returned 404. This confirms that the system needs a manifest-based path validator before deployment.

## 9. Plug-together contract

Every recovered program should eventually implement a shared machine manifest:

```ts
interface MachineManifest {
  machineId: string;
  title: string;
  role: string;
  category: 'core' | 'terminal' | 'brain' | 'vector' | 'visualizer' | 'storage' | 'portal' | 'agent' | 'archive' | 'nursery';
  octave: 'base' | 'octave2' | 'archive' | 'nursery' | 'experimental';
  inputs: string[];
  outputs: string[];
  mounts: string[];
  routes: string[];
  capabilities: string[];
  dataSchemas: string[];
  status: 'active' | 'partial' | 'archived' | 'recovery-pending';
  provenance: string[];
}
```

Machines exchange records through typed messages, not direct assumptions about another repository’s internal file paths.

```ts
interface MachineMessage<T = unknown> {
  id: string;
  from: string;
  to: string;
  type: string;
  createdAt: string;
  correlationId?: string;
  evidence?: string[];
  payload: T;
}
```
